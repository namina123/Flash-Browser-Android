# Flash-Browser-Android 解耦规划

这个文档放在仓库根目录 `docs/`，不会被 Android 打包进 APK。

## 目标

当前项目的核心耦合点集中在 `MainActivity.java`：

- 浏览器壳 UI
- `WebView` 生命周期与注入
- 本地资源映射与代理请求
- 触摸/悬停/全屏输入桥接
- Cookie 管理
- 功能面板状态
- 每日任务队列
- 仓库记录

后续一段时间的主要任务就是逐步把这些职责拆开，降低单文件状态共享和回归风险。

## 原则

1. 不做一次性大重构。
2. 每一阶段都要求可编译、可回归验证。
3. 先拆“状态存取”和“纯逻辑”，后拆 `WebView` 与输入链路。
4. 新抽离类优先保持 Java，实现低风险迁移。

## 阶段划分

### 第一阶段：偏好设置与面板持久化抽离

目标：

- 把 `SharedPreferences` 读写从 `MainActivity` 抽出
- 统一管理面板设置、方向设置、字体设置、仓库记录 JSON
- 让 `MainActivity` 不再直接拼偏好 key

预计收益：

- 降低 Activity 对持久化细节的耦合
- 为后续把功能面板整体抽成控制器打基础

风险：

- 低

### 第二阶段：功能面板控制器抽离

目标：

- 抽出面板初始化、标签切换、Cookie 列表渲染、任务启动参数收集
- 让 `MainActivity` 只保留“创建/显示面板”的入口

预计收益：

- 明显缩短 `MainActivity`
- 面板功能迭代时不再频繁碰浏览器主链路

风险：

- 中

### 第三阶段：仓库记录模块抽离

目标：

- 抽出仓库记录选择状态、对比渲染、屏蔽项操作
- 让 `MainActivity` 不再直接维护仓库记录页面状态

预计收益：

- 清理当前仓库记录旧/新版方法并存的问题

风险：

- 中

### 第四阶段：请求代理与注入逻辑抽离

目标：

- 抽出 `shouldInterceptRequest` 相关处理
- 分离本地映射、Ruffle 资源、代理请求、HTML 注入

预计收益：

- 把网络/资源链路从 UI 壳里独立出来

风险：

- 中到高

### 第五阶段：输入桥接与全屏控制抽离

目标：

- 抽出触摸转鼠标、悬停、点击桥接
- 抽出全屏切换与按钮状态控制

预计收益：

- 把最容易回归的复杂交互逻辑隔离

风险：

- 高
